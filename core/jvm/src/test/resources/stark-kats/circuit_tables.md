# Recursion-circuit data tables + transcript capture — file schemas

Generated by `stark-kat` (`cargo run --release --bin circuit_extract` and
`--bin transcript_capture`). Deterministic: re-running is byte-identical.

Oracle versions (pinned in `stark-kat/Cargo.toml` to EXACTLY what the Rust
Ergo node's `Cargo.lock` resolves for risc0-verifier v0.11.0 — the devnet
verifies with this resolution):

- `risc0-zkp 3.0.4` — the STARK verify core the succinct path runs on
  (`src/verify/mod.rs`, `src/adapter.rs`, `src/taps.rs`).
- `risc0-circuit-recursion 4.0.4` — the recursion circuit (taps, poly-ext op
  table, control IDs).
- `risc0-verifier v0.11.0` (zkVerify, git tag) — entry-point oracle; its
  vendored `circuit/v3_0/recursive/*` tables are byte-identical to the
  recursion crate's.
- `risc0-binfmt 1.2.6` — `read_sha_halfs` / claim tagged-struct digests.

General TSV conventions: `#` lines are comments; fields are TAB-separated;
lists inside a field are comma-separated decimal `u32` unless noted.
**Number forms:** Digest words (Merkle roots, `mix` inputs, `hash_pair`
inputs/outputs, all `hash_*` outputs) are the RAW `Digest` u32 words —
for Poseidon2 these are **Montgomery-form** BabyBear residues (R = 2^32),
each `< p = 2013265921`. Field-element values (`elem`/`ext`/`bits` results,
`hash_elems`/`hash_ext_elems` inputs, `ck` element lists) are **standard-form**
u32 (`as_u32()`). Ext-field elements are 4 consecutive u32s `[c0,c1,c2,c3]`
(x^4 + 11, c0 = subfield part).

## circuit_taps.tsv

The recursion circuit's `TapSet` (risc0-zkp 3.0.4 `src/taps.rs`), extracted
via the public `CIRCUIT.get_taps()`.

- `meta	group_names	accum,code,data` — register-group order; group ids
  0/1/2 are ACCUM/CODE/DATA (risc0-zkp `adapter.rs:27-29`).
- `meta	group_begin	0,16,39,643` — tap-index range per group
  (group g's taps are rows `[group_begin[g], group_begin[g+1])`).
- `meta	group_size	12,23,128` — column count per group
  (`last offset + 1`), i.e. the Merkle-leaf row widths.
- `meta	reg_count	163` — number of registers (a register = a run of taps
  sharing group+offset; its taps differ only in `back`).
- `meta	combos_count	5`, `meta	combo_begin	0,1,3,9,15,20`,
  `meta	combo_taps	…20 values…`, `meta	tot_combo_backs	20` — the "combo"
  tables: combo c's back-set is `combo_taps[combo_begin[c]..combo_begin[c+1]]`.
  `combo_u` (DEEP-ALI fold) has `tot_combo_backs + 1 = 21` ext entries.
- `tap	<idx>	<group>	<offset>	<back>	<combo>	<skip>` — 643 rows, in
  canonical order. `skip` = number of taps in this register (repeated on
  every tap of the register); a register starts at each row where the
  cumulative skip boundary lands (walk: first tap of first register is row
  0; the next register starts `skip` rows later — exactly risc0-zkp
  `RegisterIter`).

## circuit_polyext_ops.tsv

The complete constraint system as data: `PolyExtStepDef` from
risc0-circuit-recursion 4.0.4 `src/poly_ext.rs` (private module — a vendored
copy lives at `stark-kat/src/vendored/recursion_poly_ext.rs` and is asserted
equivalent to the crate's own table by evaluating both on identical inputs).

- `meta	ops_count	12359`, `meta	ret	1228` — result = `mix_vars[ret].tot`.
- `meta	fp_vars	11130`, `meta	mix_vars	1229` — final stack sizes
  (`fp_vars = ops_count - (ret+1)`, asserted).
- `meta	opcode_histogram	…`, `meta	blake2b256	<hex>` — table integrity;
  the hash is Blake2b-256 over the UTF-8 concatenation of
  `"<mnemonic>:<comma-operands>\n"` for every op in order (the parsed table,
  not the file bytes — recompute it after parsing to assert integrity).
- `op	<idx>	<mnemonic>	<comma-operands>` — 12,359 rows. Interpreter contract
  (risc0-zkp 3.0.4 `src/adapter.rs:154-392`; two append-only stacks, `fp` of
  ext elems and `mix` of `(tot, mul)` ext pairs; operand indices are
  positions in those stacks):

  | mnemonic | operands | effect |
  |---|---|---|
  | `Const` | `v` | push fp: base elem `v` lifted to ext |
  | `ConstExt` | `c0,c1,c2,c3` | push fp ext elem (0 occurrences in this circuit) |
  | `Get` | `tap` | push fp: `u[tap]` (`u` = eval_u vector, 643 entries) |
  | `GetGlobal` | `arg,off` | push fp: `args[arg][off]` lifted; `args[0]` = out (32 elems), `args[1]` = accum-mix (20 elems) |
  | `Add`/`Sub`/`Mul` | `a,b` | push fp: `fp[a] op fp[b]` |
  | `True` | — | push mix `(tot=0, mul=1)` |
  | `AndEqz` | `c,i` | push mix `(c.tot + c.mul*fp[i], c.mul*POLY_MIX)` |
  | `AndCond` | `c,cond,i` | push mix `(c.tot + fp[cond]*mix[i].tot*c.mul, c.mul*mix[i].mul)` |

  where `POLY_MIX` is the transcript-drawn constraint mixer.

## circuit_params.tsv

`param	<key>	<value>` rows: `proof_system_info` (`RISC0_STARK:v1__`),
`circuit_info` (`RECURSION:rev1v1`), `output_size` 32, `mix_size` 20,
`queries` 50, `inv_rate` 4, `ext_size` 4, `check_size` 16, `fri_fold` 16,
`fri_fold_po2` 4, `fri_min_degree` 256, `min_cycles_po2` 13,
`max_cycles_po2` 24, `min_lift_po2` 14, `hashfn` (`poseidon2` — the JVM
verifier must hard-require this suite), `allowed_control_root` (hex32),
`allowed_control_ids_count` 27.

- `control_id	<idx>	<hex32>` — the 27 `ALLOWED_CONTROL_IDS` (leaf order of
  the Poseidon2 Merkle tree whose root is `allowed_control_root`).
  NOTE: the agentB architecture report said 28; the crate lists 27
  (1 identity + 3 join + 9 lift + 9 lift_povw + 3 resolve + 1 union +
  1 unwrap_povw). The code is authoritative.
- `named_control_id	<name>	<hex32>` — the 32-entry `POSEIDON2_CONTROL_IDS`
  (informational; names for the allowed set plus po2-13/23/24 variants that
  are NOT in the allowed set).
- `fri_min_degree` / `fri_fold_po2` are private consts (risc0-zkp 3.0.4
  `src/lib.rs:54,48`) — the only two values not extracted programmatically.
- Not emitted: `SHA256_CONTROL_IDS` and `BN254_IDENTITY_CONTROL_ID` — not
  reachable from the poseidon2 succinct profile the EIP pins.

## transcript_capture.tsv

The master KAT: the complete, ordered Fiat-Shamir transcript of the REAL
devnet receipt (`proof_inner.bin`, po2=18) through risc0-zkp 3.0.4
`verify::verify` with the recursion circuit, recorded by delegating wrapper
`HashFn`/`Rng` implementations (no crate patched; the untouched verifier
accepts through the identical path — asserted at generation, along with the
recorded stream being byte-identical between the untouched driver and the
checkpoint-instrumented one).

Header comments carry `po2/tot_cycles/domain/queries/fri_rounds/final_degree`
and per-kind event counts. Event rows, in exact execution order:

- `mix	<8 words>` — `Rng::mix(digest)`: the committed digest's raw words.
- `elem	<v>` — top-level `random_elem()` result (only the 20 accum-mix
  draws appear; draws made internally by `random_bits`/`random_ext_elem`
  are not separately logged, matching the trait-call granularity a JVM
  port implements).
- `bits	<n>	<v>` — `random_bits(n)` result (the 50 FRI query positions,
  n = log2(domain) = 20).
- `ext	<4 words>` — `random_ext_elem()` result (exactly 6: poly_mix, z,
  fri_batch_mix, 3 FRI round mixes — each also labeled by a `ck` line).
- `hash_pair	<a 8w>	<b 8w>	<out 8w>` — every Merkle node hash (group-tree
  top rows, branch verifies, control-ID inclusion proof), raw digest words.
- `hash_elems	<n>	<n values>	<out 8w>` — `hash_elem_slice` calls: the two
  protocol-info strings (n=16), the out+po2 slice (n=33), every Merkle leaf
  column (n = 12/23/128/16/64), the FRI final poly (n=256).
- `hash_ext_elems	<n>	<4n values>	<out 8w>` — the single coeff_u hash
  (n=659 ext elems).
- `ck	<label>	…` — checkpoint lines interleaved at their exact transcript
  position (values standard-form unless hex): `seal_words`, `po2`,
  `tot_cycles`, `domain`, `out` (32), `group_root code|data|accum` (raw
  digest words), `control_id_included` (hex), `mix` (20), `poly_mix` (4),
  `z` (4), `coeff_u_committed` (count; the values are the preceding
  hash_ext_elems input), `eval_u` (count + 643 ext = 2572 values),
  `result` (4; the interpreted constraint value — equals the check poly,
  asserted), `fri_batch_mix` (4), `combo_u` (count + 21 ext),
  `fri_round_mix_<i>` (4), `final_poly` (count + 256 values),
  `query <i> pos <v>` (50), `check_value` (4), then the claim-binding
  block: `hashfn`, `verifier_parameters` (hex), `control_id` (hex),
  `control_inclusion_index`, `control_inclusion_digests` (hex list),
  `allowed_control_root`, `seal_control_root`, `seal_output_hash`,
  `journal_sha256`, `image_id`, `post_system_state_digest`,
  `output_digest`, `claim_digest`, `expected_claim_digest` (all hex,
  asserted consistent at generation), `verdict accept`.

Replay contract for the JVM port: drive its own ReadIOP/Rng/hash over the
receipt's seal and (a) emit the same `mix`/`elem`/`bits`/`ext` sequence
byte-exactly, (b) match every `ck` checkpoint, (c) reach accept. Hash-call
rows carry full inputs so any divergence localizes to the first differing
line. Note: intermediate per-query FRI fold goals are not separately
checkpointed; a query failure localizes via that query's `hash_elems`
column openings and `hash_pair` branch rows.
